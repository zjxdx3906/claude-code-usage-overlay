# Claude Code 实时用量浮层

在 VS Code 的 Claude Code 对话面板里常驻一枚毛玻璃胶囊，实时显示上下文占用、输入/输出 token，以及按 DeepSeek 人民币价目算出的费用。

```
◐ 12%   ↑23.1k  ↓1.6k   ¥0.041
```

悬停或点击展开明细卡片：上下文进度条、输入(未命中)/缓存读取/缓存写入/输出 的分项 token 与金额、本会话/本回合切换、当前模型与高峰/空闲时段。可拖动，位置会记住。

## 为什么需要它

两个现成方案在这里都不成立：

1. **扩展自带的用量 UI 用不了**。webview 里有 `usageData`（totalTokens/totalCost/contextWindow），但唯一的可视化是输入区那个上下文圆环，代码里写死了 `if(z>=50) return null` —— 只有占用超过 50% 才出现，而且不显示钱。
2. **CLI 自己算的钱是错的**。本机走 `api.deepseek.com/anthropic`，模型 `deepseek-flash` / `deepseek-v4-pro`。实测（对历史 `cost-state` 记录做最小二乘拟合，误差 ~1e-6）Claude Code 给这些模型套的是 **$5/M 输入、$25/M 输出、$0.5/M 缓存读取** 的兜底价，虚高 **20–35 倍**。

所以浮层用自己的价目表算钱，不走 CLI 的 `total_cost_usd`。

## 价目表（人民币 / 每百万 token）

| 模型 | 缓存命中 | 缓存未命中 | 输出 |
|---|---|---|---|
| `deepseek-v4-flash` 空闲 | ¥0.02 | ¥1 | ¥2 |
| `deepseek-v4-flash` 高峰 | ¥0.04 | ¥2 | ¥4 |
| `deepseek-v4-pro` 空闲 | ¥0.025 | ¥3 | ¥6 |
| `deepseek-v4-pro` 高峰 | ¥0.05 | ¥6 | ¥12 |

高峰 = 北京时间工作日 09:00–12:00、14:00–18:00，其余时段（含夜间、周末）走空闲价。缓存写入按未命中价计。

**用账单校准过**（示例数字，方法不变）：拿近 30 天转写按上表重算得 ¥13.9，平台同期账单 ¥12.6（1.10 倍）；只按空闲价算是 ¥12.3（0.97 倍）。两版旧表分别算出 ¥27.5（2.2 倍）和更早的 ¥27.2，都明显偏高 —— 问题出在缓存命中价填成了实际值的 2.5–6 倍，而缓存命中占了总 token 的 93%。改价后跑 `node verify-pricing.js 30 <账单金额>` 可复现。

匹配规则：价目表里**模型名含某行的名字就按哪行算**（精确找不到就取最长的子串那行）。

**加新模型时自动识别服务商**：输入 `claude-opus-5-5` 会自动标成 Anthropic、加 `qwen3-max` 标成阿里，自己加的内置行会在换到其他服务商时暂停使用（看齿轮里「仅 DeepSeek」标签）。识别不出来的型号不标服务商，到哪家都生效。

## 显示规则（避免"看着像没计费"）

**金额按数量级给小数位**，不做固定两位：

| 金额 | 显示 |
|---|---|
| ≥ ¥1 | `¥12.68` |
| ≥ ¥0.01 | `¥0.043` |
| ≥ ¥0.0001 | `¥0.0089` |
| < ¥0.0001 | `<¥0.0001` |

固定两位小数会把一个几厘钱的回合压成 `¥0.00`，看着就像根本没在计费。最后一档用 `<` 明说"有，只是太小"，而不是让 0 去冒充。悬停任何金额会给不截断的精确值。

**Token 摘要显示，悬停给精确值**：胶囊上是 `12.8K`，鼠标停上去 title 显示 `12,800 token`。

**请求还没结束时的数字会标「暂计」**：用量要等请求结束才返回时，输出行显示 `…`、金额带「暂计」后缀；落地后换成完整统计。胶囊左侧状态点悬停会说明当前是「正在统计（流式输出中）／等待用量返回／统计完成」，不只看颜色。

**「怎么这么贵」要当场回答**：合计下面常驻一行，说明钱花在哪了 ——

```
其中缓存写入占 96%（¥10.55）
```

缓存写入按「未命中」价计费，比缓存读取贵几十倍。它的来源是**每往上下文里加新内容都要重写一遍**：你的提问、工具输出、读进来的文件。所以长会话里它常常是花费大头 —— 一场 ¥11 的对话里 ¥10 花在它身上并不少见。悬停给出解释和省钱方向：少粘贴超长内容、别让工具一次吐太多、感觉跑偏了就开新会话。占比低于 15% 时这行不显示，免得占地方。

**金额前的范围标签**：胶囊上「本会话／本回合」标明这笔钱统计的是哪个范围，点开卡片可切换。

**「当前上下文」和「合计」是两回事**，卡片里专门写了一行说明：

```
当前上下文 [自动压缩线]      32K / 200K · 16%
▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░
随对话涨落，压缩后会回落；下方各项是逐次累加
刚刚自动压缩：175K → 17K，丢掉 158K
```

- **当前上下文** = 最近一次请求压在窗口里的 token 数（未命中输入 + 缓存读取 + 缓存写入），会随对话增长、自动压缩后回落
- **合计** = 本次会话每一次请求的累加，只增不减

### 分母是自动压缩线，不是模型窗口

这是刻意反直觉的一处：进度条的分母默认是 **200,000**（`autoCompactWindow`），不是 DeepSeek v4 的 1,000,000。

因为**决定「还能聊多久」的是压缩线**。CLI 认不出 `deepseek-v4-pro` 这类模型名，一律按 200k 触发自动压缩 —— 本机实测在 167K / 167K / 175K 连压了三次，1M 的窗口从来没够到过。拿 1M 当分母，界面会显示「才用了 13%，稳得很」，然后压缩毫无预兆地砸下来，前面聊的内容被总结掉一大截。用压缩线当分母，你看到的就是真实的剩余空间。

窗口标签标的是**哪个数在当分母**：

| 标签 | 含义 |
|---|---|
| `自动压缩线` | 分母是压缩线（默认；悬停会告诉你模型窗口是另一个数） |
| `手动设置` | 压缩线关掉了（填 0）或比窗口还大，改用模型窗口 |
| 无标签 | 分母来自 CLI 报的 `contextWindow`（开了 `preferCliContextWindow`） |

### 压缩发生了要说话

`compact_boundary` 一到，进度条下面就会出现一行。刚压完 3 分钟内显示具体数字，之后收成累计：

```
刚刚自动压缩：175K → 17K，丢掉 158K
已自动压缩 3 次 · 累计丢掉 470K
```

**被压缩丢掉的 token 仍然要付钱** —— 那些内容已经按输入计过费了，所以「合计」不会因为压缩而回退。压缩次数和丢掉的总量会跨窗口重载保留（见下方持久化），因为那是这一场对话已经发生的事实。

## 高峰标签能解释自己

悬停「高峰」标签（或齿轮面板里那行）会给出完整规则：现在什么价、适用时段、时区、倍率、什么时候切、切成什么。例如周二上午：

```
当前：高峰价
时段：北京时间 (UTC+8) 周一至周五 09:00–12:00、14:00–18:00
倍率：×2（相对空闲价，可在齿轮面板里改）
切换：12:00 起转为空闲价，还有约 1 小时 42 分
```

**倍率是从价目表反推的，不是写死的**。你把高峰价改成 3 倍，标签就显示 `×3`；两个模型倍率不一致会说「各模型不同」并逐个列出；同一模型内各字段倍率不同会标出区间（`×2–×3（各字段不同）`），不编一个平均值出来。关掉分时计价后页脚显示「不分时段」而不是「空闲时段」—— 后者听着像"现在是空闲档"，实际是根本没有档。

## 兼容 CC Switch 切换接入配置

CC Switch 切换接入配置时会把选中的那份 env 写进 `~/.claude/settings.json`，所以「请求实际发给谁」有一份权威答案就在那儿：`env.ANTHROPIC_BASE_URL`。

```
node provider.js          # 单独看识别结果
```

`apply.js` 每次运行都会重新读一遍并烤进配置（**每次换完配置要重跑一次 apply.js**）。认出来的服务商会显示在卡片页脚，并写明是**自动识别**还是**手动填写** —— 齿轮面板里手改过名字就标「手动填写」，填个名字不会伪装成识别成功。

**为什么要认服务商**：价目表每条都带 `provider` 标记，标明这套单价是给哪家填的。**只有当前服务商与它一致，这些数才可信** —— 不一致时那条价目直接不参与匹配。CC Switch 换到别家之后，模型名可能撞上价目表的子串：`kimi-k2-pro` 含 `pro`，要是照旧匹配，就会被按 DeepSeek 的 ¥6/M 静默算出来，差几十倍还一声不吭。现在这种根本匹配不上，会老实标成「估」并打 ⚠。

自己加的价目**不标服务商**，所以到哪家都生效 —— 你在齿轮面板里为某个模型填的价，不应该因为换了接入方就失效。

认不出来的服务商（自建中转、本机代理）不硬塞名字，标 `known:false` 并在页脚打 ⚠。

> 不读 `~/.cc-switch/cc-switch.db`。那是 SQLite，要么引原生依赖，要么按字节扫文本猜 provider 名字 —— 前者太重，后者会猜错。base_url 已经是权威信号了，不需要这个二手来源。

## 换模型时会不会骗你

**token 计数和实时涨数永远有效** —— 读的是 CLI 自己转发的流，跟接哪家 API 无关。会错的只有钱，因为价目表是写死的。

匹配只有三种结局，**后两种会在胶囊上打 ⚠**：

| 结局 | 含义 | 表现 |
|---|---|---|
| `matched` | 价目表里有这条（精确名或最长子串） | 正常显示，不报警 |
| `unpriced` | 有这条，但三个单价都是 0 | ⚠ + 卡片里点名"还没填价"，按 ¥0 记 |
| `fallback` | 完全不认识 | ⚠ + 卡片里点名，页脚单独成桶不冒充 |

规则本身只有一句：**精确名匹配，否则取最长的包含子串**，且这条价目得属于当前服务商。

**`unpriced` 不能并进 `fallback`**：新加的模型单价默认全 0，如果静默按 ¥0 算，界面会显示一个漂漂亮亮的 `¥0` —— 比不显示更能骗人。所以它照样打 ⚠，直到你填上数。

**子串匹配的方向是「模型名里含价目表的名字」**，不是反过来。所以价目表里写 `claude` 会命中 `claude-opus-5-5`，而写 `claude-opus-5-5-preview-20260101` 谁也命中不了。加价目时写短一点的通用词更划算（`qwen3` 一次覆盖 `qwen3-max` / `qwen3-plus`），这也是为什么自加的条目不该标 provider。

CLI 那边也有个对应的信号：`modelUsage[模型].costBasis`，取值 `"list"`（官方内置价）/ `"managed"`（企业托管价，现在这个）/ `"unknown"`（不认识）。

| 文件 | 作用 |
|---|---|
| `usage-overlay.js` | 浮层本体。注入到扩展 webview 里运行，只读监听消息流，不改扩展任何行为 |

## 常用命令

```bash
node test.js                  # 跑自测
node provider.js              # 看 CC Switch 现在切到了哪家
node apply.js                 # 装上 / 更新（扩展升级、或换完接入配置后重跑）
node apply.js --status        # 看装没装
node apply.js --revert        # 还原官方原版
```

改完 `config.json` 或 `usage-overlay.js` 后，重跑 `node apply.js`，再在 VS Code 里 `Ctrl+Shift+P → Developer: Reload Window`。

日常只想改价格的话不用重跑：点胶囊里的齿轮直接改，存在浏览器本地覆盖配置。

## 换模型了怎么办（不用找人）

齿轮面板里日常默认只有卡片本身（本回合／本会话、用量和花费、模型与计价规则、数据更新状态）；价格表等都收在两个折叠分区里：

- **计价设置** —— 高峰开关、上下文窗口、自动压缩线、服务商、汇率、历史费用重算、单价表（列名直接压在输入框上方：缓存读取／普通输入／输出）、加模型
- **诊断信息** —— 自检一行、事件直方图、把原始消息打到 Console

能做的：

- **改单价** —— 直接改数字，只影响之后的请求（见下）
- **加模型** —— 输入框填模型名（如 `qwen3-max`）点「添加」，会出现一行新价目，填上三个数即可
- **删模型** —— 每个模型标题右边的 `×`
- **恢复默认价目** —— 计价设置分区底部的链接

匹配规则：**精确名优先，否则模型名里包含哪行就按哪行算**（取最长的那个，不区分大小写）。所以加 `qwen3` 能一次覆盖 `qwen3-max` / `qwen3-plus`，而 `deepseek-v4-pro` 不会被 `deepseek-flash` 抢走。

**加模型时自动认服务商**：填 `qwen3-max` 会自动标成阿里，`claude-opus-5-5` 标成 Anthropic，认不出的不标（不标 = 哪家都生效）。这个标记决定换接入方之后这条价目还作不作数 —— 见上方「兼容 CC Switch」。

新增的模型单价默认全 0。**全 0 会被当成"还没填价"继续打 ⚠**，而不是静默算成 ¥0 —— 后者比不显示更能骗人。

> 界面改动存在 VS Code 的 webview 存储里。想长期保存（或换机器）就把数字抄进 `config.json` 的 `pricing.models`，重跑 `apply.js` —— 那份是跟文件走的。

## 改价只影响之后的请求（快照计价）

每条请求**落地时就定格**当时的价格快照：模型、单价、高峰／空闲时段都跟着这条记录走。之后改价、改服务商、改汇率，都不会追溯已记的条目 —— 只影响接下来的请求。**快照会跟着账本一起存盘**，所以重载窗口之后旧条目仍然按当时的价算。

需要追溯时，计价设置分区里有**「按当前价重算已记的 N 条」**：按当前价目重新定格全部记录，同时保留各自当时的高峰／空闲时段（关掉了分时计价的话，旧的高峰条目也一并按空闲价重算）。

合计永远是**按未舍入金额相加**的。分项显示各自四舍五入，肉眼相加可能差在最后一位（比如 ¥0.0012 + ¥0.0057 = ¥0.0070），这是显示精度不是算错；悬停任何金额可见精确值，卡片里也有一行说明。

## 和 CLI 自己的账对一下

CLI 在 `cost-state` 消息里也报一个 `totalCostUSD`。它那个数是**错的**（套的是官方兜底价，$5/M 输入、$25/M 输出，见文首），但把它摆出来有用：你能判断到底是浮层算错了，还是本来就该这么多。

页脚最后一行：

```
对账：  CLI ¥142.00（$20.00）· 浮层 ¥10.00
```

两边差 3 倍以上会把标签染成警示色。悬停给出完整推导、倍数，以及 CLI 是否标了 `hasUnknownModelCost`（标了就说明它自己承认不认识这个模型）。**以浮层为准** —— 价目表是按 DeepSeek 实际单价填的，可以用 `verify-pricing.js` 对账单校准。

汇率（默认 1 USD = ¥7.1）在齿轮面板「计价设置」里改。它只用于这一行换算，浮层自己的金额是按人民币单价直接算的，不经过汇率。

## 切换会话自动重新统计

检测到 `sessionId` 变了，本会话的统计立即清零重来（在途请求、压缩记录、对账数也一并清掉），不把上一个会话的数字带过来。页脚状态行会一直标「N 秒前更新」，没有新消息也会每秒兜底刷新。

## 重载窗口不清零（持久化）

浮层的账每 1.5 秒（或回合结束时立刻）写一份到 webview 的 `localStorage`（键 `cuo.acc.v1`），启动时先读回来再开始渲染。所以 `Developer: Reload Window`、切换面板、VS Code 重启之后，**这一场对话的累计不会归零**。

存的是：会话 id、起始时间、上下文占用、压缩记录，以及每条请求的 `[id, 记录]`（最多 3000 条）。记录里**带价格快照**，所以重载之后旧条目仍然按当时的价算，不会被新价重算 —— 和「改价只影响之后的请求」这条承诺保持一致。想按现价重算就点「按当前价重算已记的 N 条」。

页脚状态行会标出统计起点（`统计完成 · 3 秒前更新 · 自 14:32 起`），跨重载的时间点也是准的。

> 存档坏了不影响启动：解析失败就当没有，从零开始，不会因为读不回历史就白屏。

## 界面上一直是 0 / 不计费

先看齿轮面板里**诊断信息**分区的**自检**一行：

```
自检：收到 12 条消息，记账 5 条，最近 stream_event/message_delta
```

- **收到 0 条** → 消息通道没通（扩展升级覆盖了补丁？`node apply.js --status` 查；或 CSP 被改）
- **收到了 > 0，记账 0 条** → `ingest` 抛异常了，看 DevTools Console 里 `[usage-overlay]` 开头的报错
- **记账 > 0 但界面还是 0** → 渲染没跑起来

第三种最坑：`dirty()` 原来只用 `requestAnimationFrame` 排渲染，而 rAF 在 webview 切到后台、或 VS Code 窗口失焦时会被 Chromium 压到几乎不触发 —— 记账照常，界面却永远停在最后一次渲染上，看起来就像"聊天不计费"。现在补了 `setTimeout` 兜底，谁先到算谁。

也能在 DevTools Console 里直接问：

```js
__cuo.diag.seen            // 收到几条
__cuo.acc.entries.size     // 记了几条
__cuo.totals("session")    // 当前合计
```

## 实现要点

- **注入方式**：`extension.js` 的 `getHtmlForWebview()` 里有唯一一处
  `<script nonce="${B}" src="${G}" type="module"></script>`，在它后面插一行加载 `webview/usage-overlay.js`。CSP 是 `script-src 'nonce-${B}'`，注入的标签复用同一个 nonce；同时把 `${$.cspSource}` 也加进 `script-src` 作为兜底。
- **数据来源**：浮层挂 `window.addEventListener("message")`，接宿主转发给 webview 的那条流。
- ⚠️ **信封是套两层的**（曾经在这里栽过，记账恒为 0）：

  ```js
  { type:"from-extension",
    message: { type:"io_message", channelId:"…", done:false,
               message: { type:"assistant", message:{ id, model, usage:{…} } } } }
                 ↑ 真正的 CLI 消息在这一层
  ```

  宿主用 `this.send({type:"io_message", channelId, message, done})` 转发，而 `send()` 又包了一层 `from-extension`。`ingest()` 入口处的 `unwrap()` 负责剥壳。webview 自己也是这么剥的（`case "io_message": streams.get($.channelId).enqueue($.message)`）。改这块时务必用 `test.js` 里 `deliver()` 那条真路径测，别只用 `send()` 直接喂 —— 后者绕过信封，测不出问题。
- **实时性**：`stream_event` 的 `message_start` 给输入 token，`message_delta` 给累计的 `usage.output_tokens`，所以在 assistant 消息落地之前数字就在涨。
- **去重**：同一个 `message.id` 在流式期间会重复推送（实测一条重复 4 次），必须按 id **覆盖**取值、跨 id 求和。无脑累加会翻好几倍。
- **计价**：按模型名模糊匹配（`/flash/`、`/pro/`），`input_tokens` 是未命中部分（不含 cache_read），`cache_creation` 按未命中价计。
- **高峰时段**：北京时间周一至周五 09:00–12:00、14:00–18:00，价格翻倍，可在设置里关掉。
- **悬停展开绑在胶囊上，不是绑在容器上**。卡片收起用的是 `visibility:hidden`，看不见但**仍占布局**，所以容器的框一直延伸到卡片那片空白 —— 绑容器上会导致鼠标隔着老远飘过空白就弹窗。收起则仍看整个容器，这样鼠标能从胶囊移到卡片上。

## 已知限制

- **扩展升级会覆盖补丁**。扩展目录换成新的版本号后，重跑 `node apply.js` 即可（幂等，不会重复注入）。想自动化可以挂个计划任务。
- **只记当前这一场对话**。重载窗口不清零了（见持久化），但**换一场对话就从零开始** —— 切 `sessionId` 时清账是刻意的。要看跨会话的历史统计得用 ccusage 这类读 `~/.claude/projects/*.jsonl` 的工具。
- **自动压缩线是手填的 200k**。CLI 不在消息里报这个数，所以是按实测（167K/175K 触发）定的一条经验线。哪天真换了触发点，在齿轮面板里改一下。
- **`managed-settings.json` 不支持高峰/空闲两档价**（schema 一个模型只能给一组单价），所以那里填的是空闲价，高峰时段 CLI 的数字会偏低约一半。浮层本身是分档的，不受影响。

## 关于 CLI 的价格修正

`modelPricing` 这个设置**只认 managed settings**，官方说明原文是 *"ignored in user, project, local and --settings sources"*，写进 `~/.claude/settings.json` 完全没用。

Windows 上唯一的位置是 `C:\Program Files\ClaudeCode\managed-settings.json`（或注册表 `HKLM\SOFTWARE\Policies\ClaudeCode`），都需要管理员权限：

```
右键 install-managed-pricing.cmd → 以管理员身份运行
```

撤销：`install-managed-pricing.cmd remove`

装好后 `/cost`、扩展自带的用量弹窗、以及 ccusage 这类读 JSONL 的工具数字都会变对。**注意这会写进系统级的企业策略目录**，影响这台机器上所有 Claude Code 会话。

价目按 1 USD = 7.1 CNY 换算，汇率变了记得改 `managed-settings.json` 里的数。
